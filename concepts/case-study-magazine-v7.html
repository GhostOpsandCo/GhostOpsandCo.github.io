AI compute procurement

Fragmented compute sourcing turned into an approval-ready procurement workflow.

Compute buyers need to compare fragmented provider options against cost, carbon, workload, region, and policy constraints without treating modeled capacity as guaranteed inventory.

Public product foundation Optimization OR-Tools Next.js FastAPI Supabase
Role

Product direction, information architecture, procurement workflow, optimization requirements, UX/UI, data-source integration, and release controls.

Built

Public catalog input model, deterministic recommendation engine, approval packet, spend cap, and inspectable SkyPilot artifact path.

Works today

Publicly inspectable repository and working web product with public pricing inputs, carbon-intensity inputs, deterministic recommendations, and preview write protection.

Boundary

Capacity, latency, and availability are modeled. GridSynapse does not discover guaranteed inventory, reserve GPUs, provision infrastructure, or spend money.

AI financial workflow

A governed advisor path from idle-capital signal to operations handoff.

VIP advisors need a faster way to identify idle balances, compare controlled product routes, explain tradeoffs, document approval, and hand a clean packet to operations without giving an AI agent authority over client funds.

Working prototype Financial UX Human approval x402 proof-of-flow
Role

Product strategy, workflow design, UX/UI, recommendation architecture, report design, prototyping, and x402 testnet implementation.

Built

Advisor journey, deterministic route filtering, client-facing recommendation packet, internal operations packet, and paid access proof-of-flow.

Works today

Working multi-step product foundation using deterministic development data and a preserved public static artifact.

Boundary

Built while working with Gate AI. The public material does not use live client funds, a live Gate execution API, or autonomous execution.

Working method

The through-line is customer signal to testable product.

The portfolio should make the method obvious across projects: find the workflow gap, design the operating logic, build the artifact, and label what still needs real production validation.

01

Find the gap

Listen to customers and internal teams, inspect the current workflow, and identify where value is slow, risky, or unclear.

02

Design the workflow

Define the user, decision path, AI role, data boundaries, controls, and human-review points before building.

03

Build the testable version

Ship a working artifact, make it inspectable, and use feedback to decide what becomes production.
